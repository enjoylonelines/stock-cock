## 동작과 보장 범위

확정된 transactions와 transaction_items는 업데이트·삭제하지 않는다. 입출고 정정은 원거래를 상쇄하는 역거래와 대체 거래를, 취소는 역거래를 추가하고 transaction_resolutions로 연결한다. 메모 정정은 transaction_memo_notes에 사유·작성자·시각과 함께 추가한다. 기존 PATCH/DELETE는 405다. 목록에 원본·역거래·정정 거래와 상태/사유를 표시하고 메모를 바로 노출한다. 통계는 유효 거래만 집계한다.

입출고·이동·조정·제품 초기 재고가 공통 DB 쓰기 경로와 잠금을 사용한다. 정정은 순변동을 검증한 뒤 원본 연결·재고·신규 문서를 한 트랜잭션으로 반영한다. 재고 부족이면 전부 롤백한다. 정정 요청 ID와 원본별 유일 제약으로 재시도와 중복 처리를 막는다. 앱 역할은 재고/문서 직접 쓰기가 금지되고 해당 테이블에 RLS를 적용했다. DB 관리자에게 모든 우회가 불가능하다는 보장은 하지 않는다.

거래 품목에 제품명·단위 스냅샷을 보존하고, 이력이나 잔고가 있는 제품의 수량 체계 변경 및 옵션의 다른 제품 이전을 차단한다. 기존 데이터는 전환 시점의 카탈로그를 스냅샷으로 저장한다. 과거 덮어쓰기·삭제를 복원하지 않으며 과거 전체 장부와 현재 재고가 이미 일치한다고 주장하지 않는다.

90일 문서 삭제와 직접 합산 재계산 경로는 중단했다. 보존 기간과 데이터 증가량은 운영 검토가 필요하다. 이동/조정 자체의 정정 UI는 이번 범위가 아니다.
