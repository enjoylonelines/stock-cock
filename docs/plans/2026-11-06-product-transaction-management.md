- 제품/옵션은 재고와 과거 거래에서 외래키로 참조한다. 무조건 물리 삭제하면 참조 제약 또는 이력 손실 문제가 발생한다.
- 위 내용은 로컬 소스 확인 결과다. 운영 DB 스키마·정책 및 배포 revision과의 일치는 아직 확인하지 않았다.

## 구현 순서

### 1. 목록 메모 표시

- TransactionList의 거래 카드 하단에 비어 있지 않은 메모를 기본 노출한다. 단일·다품목 거래 모두 동일하게 처리한다.
- 줄바꿈과 긴 단어를 보존한다. 일반 메모는 클릭 없이 읽고, 긴 메모는 목록 내 펼치기로 전체를 읽는다.
- 메모 펼치기 버튼이 카드 상세 이동이나 품목 펼치기를 동시에 실행하지 않도록 이벤트와 키보드 동작을 분리한다.
- 완료 기준: 모바일에서 단일/다품목, 빈 메모, 긴 메모, 여러 줄 메모가 레이아웃을 깨지 않고 확인된다.

### 2. 제품 등록 보완 및 삭제

- 기존 등록·수정 흐름을 재사용하고 등록 → 목록 반영 → 상세 진입을 확인한다.
- 제품/옵션 등록을 단일 DB 트랜잭션으로 묶어 부분 등록을 방지한다.
- 삭제는 제품 전체와 옵션 단위의 경계를 UI에서 명확히 한다. 1차안은 제품 전체 삭제다.
- 제안 정책: 모든 옵션의 창고별 재고가 0인 경우에만 삭제를 허용한다. 창고 간 합계 0만으로 허용하지 않는다.
- 제안 정책: 과거 거래가 있는 제품은 비활성화하여 신규 선택/기본 제품 목록에서 제외하고, 과거 이력과 이름은 유지한다. 거래 없는 제품만 참조 확인 후 물리 삭제할 수 있다.
- 조회 경로(제품 목록, 선택 화면, 상세, 이력)를 함께 점검하고 비활성 제품의 과거 이력이 사라지지 않게 한다.
- 확인 창에 제품명과 범위를 표시하고, 실패 시 이유를 안내한다. 등록/삭제 성공 후 관련 캐시를 갱신한다.

### 3. 입출고 수정·삭제와 재고 정합성

- 상세 화면에 수정·삭제 동작을 추가한다. 1차 범위는 in/out이며 move/adjust는 별도 변경 없이 유지한다.
- 수정 범위 제안: 메모, 거래일, 거래처, 창고, 품목/수량. 거래 유형의 입고↔출고 전환은 제외한다.
- 메모 등 재고와 무관한 수정은 재고를 변경하지 않는다.
- 수량/창고/품목 수정은 기존 효과 역산과 새 효과 반영을 단일 RPC/DB 트랜잭션으로 처리한다. 예: 입고 10→6은 해당 재고 -4, 출고 10→6은 +4.
- 삭제는 기존 입고 효과를 차감하고 출고 효과를 복구한다. 사용자 목록에서는 제거하되 취소 기록과 변경 전후 값·작업자·시간을 보존하는 방식을 제안한다.
- 영향받는 제품 옵션/창고 키를 일정 순서로 잠근다. 기존 생성 경로와도 같은 잠금 규약을 사용하고, 재고 행이 아직 없는 경우의 동시 생성까지 처리한다.
- 상품 유형은 요청값을 신뢰하지 않고 DB에서 확인한다. 완제품은 EA, 원재료는 정수 g 규칙을 유지한다.
- 버전 또는 갱신시각으로 오래된 화면의 덮어쓰기를 거부한다. 중복 요청과 재시도로 재고가 두 번 변경되지 않게 한다.
- 제안 정책: 취소·수정 결과 창고별 재고가 음수가 되면 거부하고 사유를 표시한다. 뒤이은 출고가 있는 입고 취소도 이 기준으로 검증한다.
- 인증된 세션에서 작업자를 결정하고 DB 함수 실행권한·접근정책을 함께 검증한다. 요청 body의 user_id를 작업자 증거로 사용하지 않는다.
- 성공 시 거래 이력, 재고, 제품 상세 캐시를 갱신한다. 다른 화면에서도 UPDATE/DELETE/취소 상태 변경을 반영한다.

## 구현 전 결정이 필요한 정책

다음은 사용자가 확정한 요구가 아니라 구현 제안이다. 구현 시작 시 확정한다.

1. 제품 삭제: 재고 0 조건 및 이력 있는 제품의 비활성화 허용.
2. 입출고 삭제: 감사 기록을 남기는 취소 방식, 수정 가능 필드 범위.
3. 권한: 로그인 사용자 전체가 수정·삭제 가능한지, 작성자/관리자로 제한할지.
4. 음수 재고 금지 적용 범위와 기존 음수 데이터 처리.
5. 현재 90일 경과 거래 정리 작업과 새 취소/감사 기록의 보존 관계. 과거 이력 재계산은 삭제된 거래 전체를 합산하지 말고 현재 재고에 변경 차이만 반영해야 한다.

## 검증과 완료 기준

- UI: 메모 기본 표시/목록 내 펼치기, 다품목 메모 중복 방지, 기존 카드 조작, 제품 등록·삭제 확인/실패/중복 클릭.
- DB 통합: 완제품/원재료, 입고/출고 수정과 취소, 창고/품목 변경, 다품목 중 하나 실패 시 전체 롤백.
- 동시성: 같은 거래의 중복 취소, 동시 수정 충돌, 생성과 수정의 동시 재고 변경, 최초 재고 행 생성 경쟁.
- 권한: 비로그인 거부, 허용 범위 밖의 사용자 거부, 직접 RPC 우회 검증.
- 이력 보존: 비활성 제품의 과거 표시, 취소/감사 기록, 90일 정리와 현재 재고 유지.
- 변경 관련 Jest 테스트, 타입 검사, 변경 파일 정적 검사, webpack 프로덕션 빌드, 모바일 화면 수동 확인.
- DB 검증은 격리된 로컬/개발 DB에서 수행한다. 운영 DB 변경과 배포는 별도 실행 범위로 둔다.
- 종료 기준: 요청된 화면 동작과 위 정합성/권한 검증 통과 후 결과와 미검증 항목을 보고한다.
